## 1. 背景与目标

### 1.1 一句话

在已有 AI Gateway Platform 之上新增**多模型智能路由决策层**，把网关从"被动转发"升级为"主动决策"：请求不指定模型时，系统依据请求特征、租户预算、延迟 SLA、模型实时健康与质量，自动选择最优模型；指定模型时，仅在约束下放行或按现有降级链兜底。

### 1.2 要解决的核心矛盾

不同 LLM 的定价与能力差距显著，同一请求走强模型和弱模型的成本可能相差一个数量级，而多数请求并不需要最强模型。已有网关只解决"接得住、算得清、扛得住"，路由是"客户端指定 + 故障降级"，不解决"该用哪个模型"的问题。本模块补上决策层。

### 1.3 与基线系统的关系

| 阶段 | 解决的问题 | 核心能力 |
|---|---|---|
| 第一版（DB-design，已有） | 接得住、算得清、扛得住 | 统一入口、OpenAI 兼容、SSE、精确计费、原子配额、降级补偿、三级流控、ES 检索 |
| 第二版（本项目） | 选得对、省得下 | 请求特征提取、策略链路由决策、预算/SLA 约束、在线质量与延迟统计、路由可观测 |

### 1.4 本期交付物

1. 完整可运行的 Web-design 工程：后端（模块化单体）+ 前端 + SQL（init + upgrade + seed）+ 配置 + Windows 一键启停脚本 + 部署文档；
2. 路由层增量：RoutingEngine（策略链）、统计旁路更新、管理端路由分析、决策日志落库；
3. 核心链路自动化测试：两段式计费并发用例（含 kill -9 后 reconcile 回滚）、路由规则用例、SSE 流式回归用例（兑现 DB-design"零测试"批评的闭环，NFR-09）；
4. 演示与验收材料：演示脚本、基线对比数据；课程无固定报告模板，答辩材料按需另行整理（OQ-07 已关闭）。

## 3. 范围

### 3.1 In scope

- `model` 字段可选化；未指定时执行策略链智能路由；
- 请求特征提取（规则版）与复杂度分级（simple / balanced / complex）；
- 候选过滤（启用 + 健康 + 模型池 + 预算 + 延迟 SLA）、加权打分、决策记录落库；
- 结算事件进程内旁路更新 Redis 模型统计（延迟窗口 / 质量分 / 错误数）；
- 管理端路由分析看板 + 决策日志查询 + 路由总开关（管理端接口下发，无需重启）；
- `t_model` 模型池等级字段、`t_invoke_log_v2.routing_decision` 与 `agent_task_id` 列（含 upgrade SQL）；
- OpenAI 报文透传完整性（tools / tool_choice / response_format / 采样参数 / SSE tool_calls delta，FR-14）——agent 应用接入地基；
- Windows 全本机环境的一键启停脚本与部署文档（主交付轨）。

### 3.2 Out of scope（明确不做）

- 不引入大模型/训练分类器做特征提取（规则版即可，留扩展点）；
- 不新增中间件、不新增核心业务表（预扣流水表为选型书 M2 既有交付，非本项目新增）；
- 不改变计费口径（仍按实际应答模型千 Token 计价）；
- 不接外部付费模型 API（仍走本地 Ollama）；
- 不做 A/B 实验平台、不做权重自动调优；
- 不做 agent 编排/工具执行（LangGraph 应用为独立后续项目，本网关只做其接入底座：FR-14 透传 + 任务归因，见 8.4）；
- 不实现 `/v1/embeddings` 与 Anthropic `/v1/messages` 协议（v3 预留，见 8.4）。

```

```
请求流转（含智能路由）
POST /v1/chat/completions
  → 解析 model 字段
      ├─ 指定 model：校验存在且启用 → 基线流程（routing_decision=null）
      └─ 未指定：RoutingEngine
            → 特征提取（长度/代码/问题数/轮次）

### 4.x 与已有能力的关系

- **路由是事前选择，降级是故障兜底**，两者互补：降级不省钱，路由才是成本杠杆；降级成功后按实际应答模型计价（基线规则不变），降级事件记入 routing_decision。

## 6. 关键业务规则（需求级口径）

### 6.1 复杂度分级（规则版）

| 特征 | 提取方式 | 用途 |
|---|---|---|
| 输入长度 | messages 总字符 / token 估算 | 成本预估、复杂度 |
| 是否含代码 | 正则匹配代码块/关键字 | 复杂度加分 |
| 问题数量 | 问号/分句统计 | 复杂度加分 |
| 会话轮次 | 历史消息数 | 上下文成本 |
| 租户等级 | 用户表字段 | 仅参与候选池，不参与复杂度 |

- 输出 **simple / balanced / complex** 三级，规则打分映射；
- **打分表 v3.0 定稿（OQ-02 关闭）**：

| 特征 | 规则 | 权重 |
|---|---|---|
| 长度 | est_input_tokens < 500 → 0 分；500~2000 线性 0~1；> 2000 → 1 分 | 0.35 |
| 代码 | 命中 ``` 围栏，或正则 `(def |class |function |public |private |import |SELECT )` | 0.25 |
| 问题数 | ≥3 个问号或分句 → 1 分；1~2 → 0.5 分 | 0.20 |
| 轮次 | 历史消息 ≥6 条 → 1 分；否则 0 | 0.20 |

  - token 估算：中文约 1 字 ≈ 1 token，英文约 4 字符 ≈ 1 token；
  - `complexity_score = Σ 特征得分 × 权重`：< 0.33 → simple；< 0.66 → balanced；≥ 0.66 → complex；
  - 输出 token 预估（预算过滤用）：`est_output = min(est_input × 0.5, 2048) + 128`；
  - 后续可替换为小分类器（扩展点保留，特征提取接口化）。

### 6.2 过滤与打分

- 顺序：候选模型池 → 预算过滤 → 复杂度匹配 → 延迟过滤 → 加权打分 → top1；
- 预算过滤：预估成本 = 估算输入 token × 输入单价 + 预估输出 token × 输出单价（输出 token 预估口径见 OQ-02）；预估成本 ≤ min(请求级预算头, 租户剩余配额)，否则剔除；
- 复杂度匹配：simple 仅便宜池，complex 仅强模型池，balanced 全池；
- 延迟过滤：带 `X-Latency-SLA` 时，剔除预测延迟（近 N 次 P95）超标者；
- 打分：`score = w_q × 归一化质量分 − w_c × 归一化单价`；**w_q / w_c 默认 0.6 / 0.4（OQ-01 关闭）**，管理端配置接口热更新（进程内缓存刷新，无需重启）；
- **冷启动回退（v3.0 新增）**：Redis 统计样本数 < 20 时，质量分与预测延迟按 `t_model` 静态 baseline 字段（baseline_quality / baseline_latency_ms，种子数据预置、管理端可改）取值，避免新装环境路由行为不稳定；
- 质量代理分公式（非空/未拒答/结构合理如何折算）按 OQ-03 建议值执行：非空(1) + 未拒答(1) + 结构合理(1) 归一化到 [0,1]。

### 6.3 降级与路由的关系

- 路由是事前选择，降级是故障兜底；两者叠加不互斥；
- 降级成功后计费单价、MQ 消息、响应 `model` 字段均按实际应答模型（基线规则不变），`routing_decision` 记录降级事件。
