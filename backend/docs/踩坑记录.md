## 1. 环境与工具链

### 1.1 PowerShell 5.1 语法陷阱
- **现象**：`&&` 报错、`??` 不识别、`-LiteralPath` 下通配符失效。
- **原因**：Windows PowerShell 5.1 不支持 `&&`/`||` 链式与 null 合并操作符；`-LiteralPath` 按字面处理路径。
- **解法**：用 `cmd1; if ($?) { cmd2 }` 链依赖命令；删通配文件用 `-Path`；写 UTF-8 文件显式 `[System.Text.Encoding]::UTF8`。

### 1.2 工具大参数 JSON 解析失败
- **现象**：单次写入大文件（>10KB）报 "JSON parsing failed … Unterminated string"。
- **原因**：工具入参传输层对超长字符串截断。
- **解法**：单次 write 控制在 ~6KB 内；大文件先 write 主体 + 尾部 marker 注释，再用 edit 分段替换补全（LoginView/Sidebar 均如此完成）。

### 1.3 JAVA_HOME 每次会话都要设
- **现象**：新 shell 里 `mvn` 报 "JAVA_HOME not found"。
- **解法**：构建前统一 `$env:JAVA_HOME="D:\Java\jdk\jdk-21.0.6"`，Maven 用绝对路径 `D:\Java\Maven\apache-maven-3.9.11\bin\mvn.cmd`。

### 1.4 Windows bat 三连坑：UTF-8 解析错位 / 块内括号 / timeout
- **现象**：bat 用 cmd 直接调用时报 `'??xxx' is not recognized`、乱码命令被执行、或 "Input redirection is not supported" 循环刷屏。
- **原因**：① cmd 按 ANSI(GBK) 逐行解析 bat，UTF-8 中文注释 + 中途 `chcp 65001` 会让续读字节偏移错位，后续行从多字节字符中间开始执行；② 括号代码块内 `echo xxx (yyy)` 的 ASCII `)` 会提前闭合块（旧中文版用全角括号侥幸存活，改英文即翻车）；③ `timeout /t` 需要交互式控制台 stdin，非交互调用（工具链/CI）直接报错。
- **解法**：bat 一律**纯 ASCII**（注释用英文，不依赖 chcp）；块内 echo 不写 ASCII 括号（或 `^)` 转义）；延时用 `ping -n 3 127.0.0.1 >nul`。已按此修复 `backend\scripts\start|stop-all-windows.bat` 与 `backend\monitoring\start|stop-monitoring.bat` 四件套。

### 1.5 工具链超时会连带杀掉 start 拉起的子进程
- **现象**：通过命令工具跑 start-all-windows.bat（超时上限 150s）后，网关 java 进程莫名消失，Redis 却存活。
- **原因**：`start` 拉起的子进程若继承工具管道的写端，命令超时被强杀时整个管道树连带被杀（java 继承了管道句柄，redis-server 自行 detach 幸存）。
- **解法**：拉长驻进程一律用 `Start-Process cmd /c script.bat -WindowStyle Hidden` 脱离工具管道启动，端口就绪另行轮询；stop 类脚本无长驻子进程可直接跑。

### 1.6 bat 括号块内 `%errorlevel%` 冻结（Redis 自启误报 FAIL）
- **现象**：Redis 未运行时跑 start-all-windows.bat，`:start_redis` 明明成功（进程已起、6379 已监听），却报 `[FAIL] Redis 6379 not listening and auto-start failed` 中止启动。
- **原因**：`if ... ( ... )` 块在**解析期**一次性展开全部 `%errorlevel%`，块内读到的永远是进块前的旧值（check_port 失败残留的 1），子过程真实返回码被掩盖。此前未暴露只因历次启动 Redis 都已在跑，该分支从未真正走到。
- **解法**：顶部已有 `setlocal enabledelayedexpansion`，块内改用 `!errorlevel!`（或 `if errorlevel 1` 动态语义）。修复后 backend\start-all.bat / backend\stop-all.bat 全栈双向实测通过。

### 1.7 cmd 的 CALL 对带引号相对名不做 PATH 搜索（静默 RC=1）
- **现象**：build-release.bat 里 `where mvn` 能找到 Maven，`call "mvn" -q clean package` 却静默失败——零输出、RC=1；`call "mvn.cmd"` 同样死。
- **原因**：cmd 的 CALL 对**带引号的相对名**不执行 PATH 搜索（只查当前目录），失败时不打印任何错误。四路实测：`call "mvn"` ✗ / `call "mvn.cmd"` ✗ / `call mvn` ✓（裸名走 PATH+PATHEXT）/ `call "绝对路径\mvn.cmd"` ✓。`where` 找得到 ≠ `call "名字"` 跑得动。
- **解法**：调用前解析成**绝对路径**再 call（已知路径直取，否则 `for /f "delims=" %%i in ('where mvn.cmd 2^>nul') do set "MVN_CMD=%%i"`）。已修复 scripts\start-all-windows.bat 的 -build 路径（历史遗留同款，因该分支从未走过而潜伏；曾短暂存在的单体版 build-release.bat 已随方案回滚移除，再写构建类 bat 记得同规则）。附带教训：构建类 bat 慎用 `-q`——静默模式吞掉全部 [ERROR] 输出，排障无从下手。

### 1.8 PS 管道消费含 `start` 的 bat 输出 → 下游 cmdlet 永久挂起
- **现象**：`cmd /c start-all-windows.bat` 后接 PS 管道（如 `| Select-Object`）——bat 已执行完毕、应用已正常拉起（java 在跑、10011 已监听），但命令不返回，挂到超时被杀；同一 bat 不接管道裸跑正常返回。
- **原因**：bat 内 `start` 拉起的长驻子进程继承了重定向进管道的 stdout/stderr 写句柄；bat 的 cmd.exe 退出后，管道写端仍被 java 持有，EOF 永不到达，下游 cmdlet 一直阻塞。与 1.5 同根（管道句柄继承），症状相反：1.5 是超时被杀连坐子进程，本条是上游正常退出、下游永等。
- **解法**：会 `start` 长驻子进程的 bat 一律不接任何 PS 管道（裸跑 `cmd /c bat`）；需留输出让 cmd 自己重定向到文件（`cmd /c "bat > log.txt 2>&1"`，文件句柄不进 PS 管道），事后读文件。

### 1.9 PS 5.1 Invoke-RestMethod 对无 charset 的 UTF-8 JSON 按 Latin-1 解码（中文断言假阴性）
- **现象**：接口返回中文与期望值实际相等（curl/DB 双确认均为正解），`Invoke-RestMethod` 结果的字符串比较却判 False，打印为「æµ‹è¯•」式乱码。
- **原因**：Spring 返回 Content-Type: application/json 不带 charset，PS 5.1 找不到 charset 时回退 ISO-8859-1 解码字节流，UTF-8 中文全花。
- **解法**：改 `Invoke-WebRequest -UseBasicParsing -TimeoutSec 30`（PS 5.1 该参数默认无限，务必显式给值），再 `[Text.Encoding]::UTF8.GetString($raw.RawContentStream.ToArray())` 显式 UTF-8 解码后 `ConvertFrom-Json`；中文断言由假阴性转真阳性。

## 2. 后端：SSE / 异步

### 2.1 SseEmitter 包进 ResponseEntity 报错（最高频）
- **现象**：`No converter for SseEmitter with preset Content-Type text/event-stream`。
- **原因**：SseEmitter 必须走 Spring 异步专用返回值处理器；包进 ResponseEntity 会落入消息转换器路径。
- **解法**：控制器**裸返回** emitter；自定义响应头（X-Routing-Decision）改走 `HttpServletResponse.setHeader()`，异步首帧提交时一并生效。见 ChatController。

### 2.2 SSE wire 格式：`data:` 后无空格
- **现象**：前端解析 chunk 时多出一个前导空格或首字符丢失。
- **原因**：网关手工拼帧用 `data:` + JSON，无标准空格。
- **解法**：前端统一 `slice(5).trim()` 解析；`data:[DONE]` 终止哨兵同样处理。

### 2.3 SSE 终止回调可能连发，计数重复扣减（v2 观测增量）
- **现象**：给 emitter 追加 onCompletion/onError/onTimeout 埋点后，在途计数出现负数。
- **原因**：`completeWithError` 之后完成回调**仍会执行**；错误回调与完成回调连续触发。
- **解法**：`AtomicBoolean.compareAndSet` 保证 endStream/endCall 恰好执行一次；同一 emitter 的三类回调均为列表语义，可多段追加，与 ChatService 内部回调共存。

### 2.4 streamChat 同步抛错时回调未注册
- **现象**：校验/预扣失败时在途计数泄漏（只增不减）。
- **原因**：`streamChat()` 对校验错误**同步抛出**，emitter 尚未创建，终止回调无从挂载。
- **解法**：控制器 try/catch 包裹 streamChat，catch 中手动 `endCall()` 再 rethrow。见 ChatController 流式分支。

### 2.5 认证错误的三套口径（勿统一）
- **现象**：客户端对错误码解析混乱。
- **约定**：`/v1/*` 返回标准 401 + OpenAI 风格 JSON（SDK 兼容）；`/api/*` 返回 HTTP 200 + `code=401`（前端 Result 协议）；普通用户访问 `/admin/*` 返回 `code=403`。JwtAuthFilter 按路径分发，改前先读 filter。

## 3. 后端：数据与并发

### 3.1 批量写队列满时的丢弃策略
- **现象**：压测时消息/账单偶发丢失。
- **原因**：BatchLogWriter 用 `LinkedBlockingQueue.offer()`，队列满（容量 1 万）直接返回 false。
- **解法**：这是**有意设计**——观测旁路绝不能阻塞主链路；调用方记日志告警。监控页（/admin/metrics/runtime）暴露队列水位，>80% 即预示下游 MySQL 写入跟不上。

### 3.2 双写一致：reserve 同步 / 日志异步
- **现象**：早期把消息落库放同步路径，QPS 陡增时 RT 抖动。
- **原因**：同步路径混入了非强一致需求写入。
- **解法**：强一致只有配额 reserve/settle（同一事务）；会话消息 + 日汇总走 500ms 攒批异步；趋势统计读 Redis 热路径。见 docs/1.md §6。

### 3.3 `INSERT ... ON DUPLICATE KEY UPDATE` 的 VALUES() 弃用警告
- **现象**：MySQL 8 下日志出现 deprecation warning。
- **原因**：8.0.20 起 VALUES() 语法进入弃用周期。
- **解法**：当前版本可用（仅警告），保留；升级 8.4+ 前再迁移到 `AS new ON DUPLICATE KEY UPDATE x = new.x` 别名语法。

### 3.4 mapper 双重注册约定
- **现象**：新 mapper 不生效或 Bean 冲突。
- **约定**：启动类 `@MapperScan` 扫四个包 + 每个 mapper 接口再加 `@Mapper` 注解（双保险）；新 mapper 放对应模块包下即被扫到，无需改启动类。

## 4. 前端

### 4.1 Element Plus 全量引入的四件套
- **现象**：组件样式错乱 / 中文丢失 / 图标不渲染。
- **解法**：全量引入必须同时做四件事：组件库本体、`element-plus/theme-chalk/dark/css-vars.css`、`zh-cn` locale、`@element-plus/icons-vue` 全局注册。少一件表现各异，排查耗时。

### 4.2 深色输入框的 Chrome autofill 白闪
- **现象**：登录页输入框被浏览器自动填充时闪白/蓝。
- **原因**：`-webkit-autofill` 内阴影覆盖背景色。
- **解法**：`-webkit-box-shadow: 0 0 0 1000px <输入框底色> inset` 强制覆盖（LoginView 用 #11161d）。

### 4.3 轮询页面必须清理定时器
- **现象**：离开监控页后请求仍在发。
- **解法**：`onMounted` 里 `setInterval`，`onUnmounted` 里 `clearInterval`；轮询失败**保留上次快照**不置空，避免依赖抖动导致页面闪空。见 MonitorView。

### 4.4 vue-tsc 严格空值
- **现象**：`p90LatencyMs` 等可空字段渲染报 TS 错。
- **解法**：模板里显式判空 `m.p90LatencyMs !== null ? ... : '-'`，禁止 `!` 断言；接口的可空字段在 types.ts 用 `| null` 显式标注（后端 JSON null 与 undefined 语义不同）。

### 4.5 vite 代理路径清单
- **约定**：dev 端口 3000，代理前缀**恰好四个**：`/auth`、`/v1`、`/admin`、`/api` → `http://localhost:10011`。新增后端路径前缀时必须同步 vite.config，否则 404 且难定位（浏览器里看到的是 3000 端口）。

## 5. UI / 设计系统

### 5.1 设计令牌"改值不改名"
- **约定**：global.css 里 `--color-primary` 等**变量名一律不动**，只改色值——所有视图按语义引用变量，改版零散页面改动。v2 控制台改版（青绿 #0f766e 主色族）只动了变量值 + 组件覆盖层。

### 5.2 Element Plus 主题映射层级
- **解法**：覆盖 EP 变量必须落在对应层级（`--el-button-*`、`--el-table-*`…），直接改 `--el-color-primary` 只影响部分组件；圆角用 `--el-border-radius-base/small/round` 三档同时压。

### 5.3 语义色板固定
- **约定**：用户 #2563eb / 模型 #0d9488 / 调用 #16a34a / 费用 #d97706 / tokens #0891b2 / 失败 #dc2626 / 中性 #94a3b8；健康分 ≥75 绿、≥50 琥珀、否则红。新增图表必须复用，避免同指标多页异色。

## 6. 数据库

### 6.1 中文全文检索必须 ngram
- **现象**：FULLTEXT 对中文查不到。
- **原因**：默认按空格分词，中文无分隔符。
- **解法**：`WITH PARSER ngram`（t_chat_message，init.sql:226）。

### 6.2 对账口径全局唯一
- **约定**：结算完成 = `success = 1 OR interrupted = 1`。所有统计 SQL（仪表盘/用量/成本）必须用同一口径，否则各页数字对不上——这是数据可信度的生命线。

### 6.3 字符集统一 utf8mb4
- **约定**：所有表 utf8mb4_0900_ai_ci；聊天内容含 emoji，utf8 会截断。连接串显式 `characterEncoding=utf8`。
